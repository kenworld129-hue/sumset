# ADR-001: プロジェクトを「家庭財務データ基盤」として定義する

- 日付: 2026-07-03
- 状態: 採用

## 背景

旧版は「家族用の家計簿アプリ」だったが、実体は Web 入力層＋夜間バッチ＋集計＋配信を持つ小さなデータ処理システムであり、看板が実体より狭かった。ポートフォリオとして語る際も「家計簿を作った」では内向きに聞こえる。

## 選択肢

- 案 A: 家庭内データ基盤として再定義（OLTP／ETL／マート／配信／品質チェックの語彙で捉え直す）
- 案 B: セルフホスト型 OSS プロダクトとして磨く（Docker 配布・導入ドキュメント整備）
- 案 C: 「AI 生成コードのリビルド・ケーススタディ」を主題にする

## 決定

案 A を看板とし、案 C を README の第一章として内包する。案 B は却下（部品の Docker 活用のみ採用）。

## 理由

構成がもともとバッチ中心＝データ処理中心であり、再定義は実体に看板を追いつかせるだけでコストが最小。データエンジニアリングの語彙（OLTP／ETL／マート／品質チェック）でそのまま語れる。案 B は認証・導入性を製品水準にする工数が過大で、利用者ゼロの「OSS プロダクト」は物語をむしろ弱くするため捨てた。ただし看板負けを防ぐため、Ingestion（明細 CSV 取込・突合）と品質チェック自動化を実装することを条件とする。
