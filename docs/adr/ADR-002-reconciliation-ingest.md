# ADR-002: 明細 CSV 取込は「置き換え」ではなく「突合」として設計する

- 日付: 2026-07-03
- 状態: 採用

## 背景

明細 CSV の自動取込を導入するが、主利用者（家族）は買い物のたびに手入力するリアルタイム運用を求めている。カード明細は反映まで数日〜1 ヶ月遅れるため、CSV では原理的にリアルタイム性を満たせない。現金取引は明細がそもそも存在しない。

## 選択肢

- 案 A: 手入力を CSV 取込で置き換える（入力レス化）
- 案 B: 手入力＝速報値、明細＝確定値とし、パイプラインは両者の突合を本業とする

## 決定

案 B。突合結果は 3 分類 — 一致→「明細確認済み」マーク／明細のみ→入力漏れ候補として提示／手入力のみ→誤入力・二重疑い警告。最終判断は人間が確認画面で行う（human-in-the-loop）。明細ダウンロード自体の自動化（スクレイピング）はスコープ外。

## 理由

案 A はリアルタイム要件と現金取引の存在により成立しない。案 B は手入力の価値を保ったまま網羅性・正確性を機械が保証する構成で、「速くて不完全なデータ×遅くて正確なデータ」というデータ基盤実務の定番構図の実践にもなる。
