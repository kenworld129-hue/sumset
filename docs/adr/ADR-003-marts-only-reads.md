# ADR-003: 分析系の画面・BI はマート層のみを読む（ファクト直読み禁止）

- 日付: 2026-07-03
- 状態: 採用（適用開始は R3 のマート誕生から）

## 背景

旧版は画面によってデータの出所がバラバラだった — 月次集計画面はサマリーテーブルを読み、収支合計画面は transactions を直接 SUM し、予実比較は両者を混ぜて JOIN していた。バッチ集計と画面集計の数字がズレ得る構造で、「どの数字が正か」が言えなかった。

## 選択肢

- 案 A: 各画面が都度 transactions を直接集計する（常に最新・実装が楽）
- 案 B: 分析系はマート（transaction_summaries 等）のみを読む。鮮度は夜間バッチ更新に従う

## 決定

案 B。ただしマートが存在しない R1〜R2 の間に限り、予実比較の実績側は transactions 直接集計の暫定実装を許す（出所が単一のためズレは起きない）。R3 でマートが誕生した時点で切替え、以降は本ルールを恒久適用する。

## 理由

数字の正が一箇所に定まり、画面間の不一致が構造的に起きなくなる。日次の家計把握に必要な鮮度は「前日まで」で十分であり、リアルタイム性が必要な情報（今月の入力一覧・残高）は分析系ではなく業務系画面の責務として分離する。
