# Git 運用ルール

開発者 1 名の個人開発なので、規約は最小にしている。

## ブランチ

- `main` に直接コミットする
- ブランチを切るのは、数日以上かかる大きな実験だけ。終わったら `main` にマージして削除する
- push 済みのコミットは書き換えない（amend・rebase・force push をしない）

## コミット

- 1 タスクにつき 1 コミット以上。リファクタと機能追加を別コミットに分けるような細かい分割はせず、外から進捗が読める単位でまとめる。README の更新は別コミットにする
- タスク ID（`R1-05` など）は「リリース番号-連番」。リリース単位の進捗管理はリポジトリの外で行っている
- 件名は次の 3 形式。接頭辞（`feat:` など）は付けず、区切りは全角コロン
  - タスク完了: `R1-05完了：Spring Boot 雛形を作成`
  - 途中コミット: `R1-05：ログイン画面の雛形を追加`
  - README 単独: `R1-05完了に伴いREADMEを更新`
- 本文は箇条書きで「何をしたか」を書く。リポジトリの外の文脈（協議の選択肢名、「前述のとおり」など）に頼らない
- 実データ・秘密情報・個人用の設定ファイルはコミットしない（`.gitignore` で除外する）

## タグ

- リリース（R1, R2, …）が完了したら、README を更新したコミットに注釈付きタグ（`git tag -a`）`r1`, `r2`, … を付けて push する
